# RFC-001 — the machine as one file

*Status: shipping — phases 1–5 landed in ewe 0.9.0. Phase 4 (static
artifacts) done; `hypridle.conf` and `monitors.lua` stay shell-generated by
design. Phase 6 (broker + sync) became RFC-005/RFC-006. Target: 1.0-beta
"Dolly".*

## The decision

Everything the user can express about the desktop lives in one declarative
TOML document, `~/.config/ewe/ewe.conf`. Settings UIs edit it, one tool
(`ewe-conf`) applies it, everything else is generated from it. **Save the
file, restore the machine.**

## Why (the drift problem it deleted)

Before: ~14 config files kept consistent by **TWO byte-identical generator
implementations** (the in-shell Settings panel and ewe-settings) — a
contract enforced by care, not architecture. Sync meant gathering many
files; install wrote them imperatively; Komble's restore list lived apart.

After: one file with one generator deletes the drift class entirely and
makes **sync, backup and install the same operation**: produce the file,
apply the file.

## The five rules (see [[The One File]] for the full mechanics)

1. One canonical file — TOML, diffable, regenerated comment headers.
2. One writer — `ewe-conf` only.
3. Everything else is generated (`hypr/generated/*`,
   `quickshell/*.json`) — build artifacts of `ewe-conf apply`.
4. Secrets never enter the file — it syncs to the cloud. Keyring only.
5. Live-apply stays with the UIs — instant `hyprctl eval`, then persist
   *through* `ewe-conf`.

## What it cost / changed

- Hand-written comments in the file do not survive (regenerated headers).
- Editing a `generated/` file works exactly until the next apply.
- `ewe-conf import` exists for migration/repair: rebuilds the document from
  what the machine is doing right now, seeds `[desktop.layout]` defaults
  and an `[apps.installed]` baseline from explicitly installed pacman
  packages.

## Anti-regression notes

- **`hypridle.conf` and `monitors.lua` stay shell-generated by design** —
  they are runtime-reactive on battery/hotplug. Don't "complete" the
  migration by moving them into ewe-conf.
- **Prefs the Settings app writes MUST be in ewe-conf's `THEME_MAP`**, or
  `absorb` drops them on the next write (that was the 0.12.7 "Top bar
  settings do nothing" bug).
- `ewe-conf` writes are atomic (tmp + rename) with `flock` around
  read-modify-write; key order is stable so diffs are honest.
- `ewe-conf set` parses values as JSON, else string; structures print as
  JSON on stdout for `get`/`dump`.
- The shell passes `--no-hooks` to `apply` (it applies live itself); from a
  terminal the full restore is `ewe-conf pull && ewe-conf apply`.
